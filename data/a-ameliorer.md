Stage encore trop léger
La partie Flotto est honnête pour un début de stage, mais elle ne respecte pas encore la fiche attendue “mission de stage” : contexte professionnel, objectif, environnement technique, démarche, livrable, preuve anonymisée, compétences techniques/transversales, recul personnel. Le fichier mission-stage.md (line 1) est encore très brut.
À faire : transformer le stage en 2 ou 3 missions concrètes, même petites : prise en main Angular, correction d’un ticket, compréhension d’un module, documentation interne, etc.

Preuves listées mais pas assez expliquées
Les preuves existent sous forme de listes, par exemple scripts/data.js (line 33), mais elles ne disent pas toujours clairement : “cette preuve montre quelle compétence, à quel niveau, grâce à quelle action ?”
À faire : pour chaque projet, ajouter une mini-section du type : compétence → action réalisée → preuve → niveau atteint → axe de progrès.

Autoévaluation encore trop générale
Le bilan actuel est propre, mais encore global : index.html (line 179). Les documents demandent une autoévaluation argumentée : difficulté rencontrée, décision prise, résultat obtenu, limite, suite.
À faire : ajouter pour chaque expérience 3 lignes très concrètes : réussi / difficile / à refaire autrement.
